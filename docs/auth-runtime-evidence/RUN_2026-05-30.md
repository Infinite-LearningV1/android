## Scenario 3 — Invalid refresh token forces login banner

Expected:

- Backend returns `AUTH_REFRESH_TOKEN_INVALID`.
- Android triggers forced reauth.
- Login screen banner: `Sesi tidak valid lagi. Silakan login lagi.`

Observed:

- App installed successfully from `app/build/outputs/apk/debug/app-debug.apk`.
- App launched to the Login surface with a forced re-auth state already present from persisted local session state.
- Local screenshots were captured during verification before and after dismissing the dialog (not committed to git).
- On-screen banner text observed: `Sesi tidak valid lagi. Silakan login lagi.`
- On-screen modal observed before dismiss: `Sesi Berakhir` / `Sesi Anda telah berakhir. Silakan login kembali untuk melanjutkan.`
- This confirms the Android consumer can surface the invalid-session reauth UX on the real app surface.
- Logcat also showed bootstrap/auth cleanup activity from `AuthRepositoryImpl`.
- Relevant observed log lines:
  - `Profile sync skipped because auth token is missing`
  - `Refresh session skipped because refresh token is missing`
  - `Server logout failed, proceeding with local logout`
  - `java.net.ConnectException: Failed to connect to /192.168.3.197:3005`
  - `Local data cleared successfully`
- This does **not** yet prove which backend code produced the state because no controlled backend response / login credential flow was available in this smoke session.
- It also shows the current emulator session cannot reach the configured backend host (`ECONNREFUSED`), so end-to-end refresh/replay smoke is environment-blocked until backend connectivity is available from the emulator.
